# GrokBotDevTeamRU

Пятая версия проекта. Prerelease 1.5.3.

Ставьте на отдельный компьютер без рабочих секретов — подробнее в разделе [«Безопасность»](#безопасность-прежде-всего).

English version: [GrokBotDevTeam](https://github.com/alexzah-droid/GrokBotDevTeam).

Это неофициальный проект, не связанный с xAI. Grok — торговая марка xAI. Правообладатель оригинального кода — alexzah-droid.

GrokBotDevTeamRU устанавливает команду разработки из трёх ботов по одному сообщению. Ваш Grok Bot становится **Руководителем** и сохраняет прежние обязанности. Он добавляет **Разработчика** для реализации и **Проверяющего** для независимой проверки. Команда уточняет запрос, планирует работу, обновляет документацию и проводит демо для приёмки.

## Встроенный цикл самоулучшения

Команда собирает сведения о повторяющихся сбоях, и бот предлагает правку своей инструкции. Независимый оценщик проверяет кандидата, а на испытании команда собирает наблюдения за его работой. В режиме с подтверждением вы отдельно одобряете запуск испытания и его результат. В автоматическом режиме контроллер принимает успешный результат сам. Если испытание провалилось или срок истёк, контроллер возвращает прежнюю инструкцию. Историю изменений можно посмотреть через `history <role>`.

## Установка

Установка работает с опубликованного тега `v1.5.3`. Отправьте сообщение ниже в чат со своим Grok Bot. Установщик проверит доступные нативные инструменты Grok Bot до создания команды и сообщит, если какой-то возможности нет.

### Сообщение на русском

```text
Установи GrokBotDevTeam из https://github.com/alexzah-droid/GrokBotDevTeamRU, prerelease v1.5.3.
Прочитай и выполни INSTALL.md из этого тега. Останься моим Руководителем, создай только Разработчика и Проверяющего.
Сначала предложи выбрать режим инструкций. По возможности помести новых ботов в свою папку.
Проверь готовность команды и предложи прислать первую задачу.
```

В [полном сообщении для установки](install-prompt.txt) указаны правила восстановления и разрешений. Первая карточка предлагает менять инструкции с подтверждением или автоматически. Автоматический режим требует второго согласия. При отказе или без ответа действует подтверждение. Руководитель размещает новых ботов в своей папке, если может её определить, или предлагает выбрать папку.

## Что входит

| Компонент | Назначение |
| --- | --- |
| Три ролевые инструкции и шесть навыков | Планирование, разработка, проверка проекта, документация, ревью и улучшение инструкций |
| Локальный контроллер и мост нативных инструментов | Состояние задач, возобновляемая установка и передачи, проверки и история версий |
| Самоулучшение и watchdog | Независимая оценка, испытания, приёмка и автоматический откат |

## Режимы самоулучшения

Общий режим по умолчанию — `approval`. Для команды можно выбрать `approval` или `autonomous`. Каждая роль наследует общий режим, пока для неё не задано исключение. Попросите Руководителя показать действующие режимы, сравнить версии или восстановить историческую инструкцию.

## Безопасность прежде всего

1. **Возможности.** Боты запускают команды, читают и пишут файлы, используют Git и сетевые инструменты, создают ботов. Установка запускает фоновый watchdog, а выбранная рутина может его перезапускать. `project verify` исполняет код проверяемого проекта.
2. **Общий компьютер.** Боты могут читать файлы друг друга. С тем же доступом они способны подделать ответ и его ID, вызвать терминальную выдачу через псевдотерминал или прямой импорт Python либо вписать грант в SQLite.
3. **Изолируйте установку.** Используйте компьютер без рабочих секретов, SSH-ключей, облачных токенов и сессии `gh` с правом записи в важные репозитории.
4. **Ограничьте доступ.** Возьмите отдельный тестовый репозиторий. Если нужен токен, ограничьте его этим репозиторием и минимальными правами. Исключите административные и производственные права.
5. **Считайте входные материалы данными.** Не вставляйте секреты в задачи и сообщения. Код репозитория, задачи из трекера, веб-страницы, вывод команд и сообщения ботов могут содержать подставные инструкции. Контракты запрещают принимать их за инструкции или согласие. Эффект зависит от поведения бота.
6. **Оставайтесь в `approval`.** Подтверждайте применение и приёмку отдельно. В `autonomous` успешные оценки и наблюдения позволяют применить и принять инструкцию без этих подтверждений.
7. **Следите за расходом.** Лимит итераций задачи — 1–10. Оценка использует бюджеты вызовов и времени. Следите за расходом и подключайте платного исполнителя только при необходимости.
8. **Аварийная остановка.** Скажите Руководителю «стоп». Отмените испытания, выполните `service stop`, приостановите или удалите двух добавленных ботов, уберите стартовое правило и удалите рабочие данные после решения, что сохранить. [Аварийная остановка](docs/OPERATIONS.md#аварийная-остановка).
9. **Проверяйте источник.** Устанавливайте из официального тега этого репозитория. Сверяйте SHA-256 архива со страницей выпуска. Не используйте форки и ссылки из чужих сообщений.
10. **Данные и гарантии.** Платформа Grok Bot обрабатывает код и задачи, которые читают боты. SQLite хранит тексты задач открытым текстом. Дополнительный исполнитель xAI отправляет тестовые входы и инструкции только при явной настройке ключа из окружения. Лицензия MIT предоставляет проект «как есть». Проект неофициальный, не связан с xAI. Grok — торговая марка xAI.

## Подтверждения и доверие

Канал по умолчанию — `chat`. Руководитель показывает дословный вопрос, регистрирует явный ответ и получает одноразовый грант со сроком действия и привязкой к действию, цели и состоянию. В штатном пути гранты `improve.approve` и `improve.accept` привязаны к разным действиям. Доступен также канал `terminal`. [Подтверждение человеком](docs/CONFIRMATIONS.md).

При новой или изменённой привязке проекта Руководитель выполняет `project bind` без карточки в общем режиме `autonomous`. В режиме `approval` Руководителю нужен одноразовый грант `project.bind`.

Чат рассчитан на доверенного Руководителя. Бот на том же компьютере может подделать ответ и `message_ref`, вызвать терминальную выдачу через псевдотерминал или прямой импорт Python либо записать грант в SQLite. До стабильного релиза запланированы выдача вне компьютера бота или подпись ключом, недоступным ботам. [Модель угроз](SECURITY.md).

## Локальная проверка

Нужны Python 3.10 или новее, Git и среда POSIX, например Linux или macOS. SQLite встроен в Python и не требует отдельного сервиса.

```text
<venv>/bin/python -B scripts/doctor.py
<venv>/bin/python -B scripts/release.py check
<venv>/bin/python -B scripts/validate_skills.py
<venv>/bin/python -B -W error::ResourceWarning -m unittest discover -s tests -v
<venv>/bin/python -B scripts/demo.py
```

Демо выполняет задачу во временном Git-проекте, затем проверяет самоулучшение с подтверждением, автономный режим и откат. [Воспроизводимые проверки](VALIDATION.md).

## Как проверить инструкции ботов

- В `bots/` лежат контракты и изменяемое поведение каждой роли. Самоулучшение может менять поведение, но не контракт.
- В `skills/` лежат рабочие процедуры. В [установочной инструкции](INSTALL.md) и [установочном сообщении](install-prompt.txt) — точные шаги создания команды.
- В `grokteam/texts.json` лежат русское стартовое правило, вопросы и подписи кнопок. Стартовое правило собирает `bootstrap()` в `grokteam/bundle.py`. Оно относится только к задачам команды.
- Служебные сообщения контроллера — на английском.

## Python-пакет

В окружении Python 3.10+ выполните `<venv>/bin/python -B -m pip install .`. Пакет `grokbotdevteam-ru` включает контроллер и ресурсы релиза. Вызывайте `grok-team` или `python -m grokteam` из любой рабочей папки. Сборка и контроллер используют стандартную библиотеку Python.

Bootstrap сохраняет пути установки и интерпретатор Python. При переносе путей нужна повторная привязка. Храните рабочие данные вне релиза и проверяемого Git-проекта. Контроллер не требует API-ключа и ничего не отправляет владельцу проекта. Дополнительный оценщик xAI отправляет провайдеру тестовые входы и инструкции только при явной настройке.
