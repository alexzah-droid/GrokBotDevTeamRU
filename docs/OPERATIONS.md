# Эксплуатация и восстановление

Пользователь общается со своим ботом-Руководителем. Технические команды ниже выполняет он; пользователю не требуется вручную обслуживать базу.

## Состояние и история

`status` показывает команду, роли, фактические режимы, проект, очередь, watchdog и эксперименты. `task show` возвращает актуальный результат. `history`, `version`, `diff` и `events` отвечают на вопросы об инструкциях. `export` выводит полный лог и все версии в JSON для локального архива; он не отправляется автору проекта.

Не храните пароль, API-ключ или токен в инструкции. Они не требуются контроллеру. Дополнительный runner использует безопасно настроенное окружение. Не включайте runtime, `.env` и ключи в GitHub-релиз.

## Watchdog

Поставляется [routine-шаблон](../routines/watchdog-restart.md) для подтверждённого на платформе автоперезапуска. Он не включён сам по себе. Сбой Exception итерации логируется, цикл продолжает работу; завершение процесса ОС требует routine или супервизора.

Руководитель запускает `service start` при восстановлении сессии и проверяет heartbeat в status. Повторный запуск при живом процессе не создаёт второй экземпляр. Лог — `<runtime>/watchdog.log`.

Пока компьютер выключен или процесс не работает, дедлайны не исполняются физически. Поэтому новые применения в native-установке требуют свежего heartbeat, а после перезапуска первый sweep возвращает просроченные версии. Для диагностики доступен `--actor controller watch --once`. Это не обход выбора режима: контроллер заново проверяет политику.

Для остановки сначала завершите/отмените trial, затем по запросу пользователя выполните `service stop`. Остановка запрашивается по токену процесса без отправки сигнала произвольному PID. Watchdog завершится при следующем цикле.

## Операция зависла после нативного вызова

1. Прочитайте bridge pending.
2. Для dispatched найдите результат в нативной истории инструментов или сообщений.
3. Если бот создан, используйте фактический agent_id и external_ref в receipt. Если результат неоднозначен — остановитесь; не создавайте нового бота «на всякий случай».
4. Повторный ack с тем же receipt безопасен; другое содержимое receipt вызывает конфликт.

У очереди нет ложного автоматического подтверждения отправки. Ошибка или отсутствие ответа сохраняет незавершённое состояние. Mock adapter используется только в тестах.

После ревью контроллер может поставить передачу Руководителю с причиной `review`, даже если он уже обработал результат. Руководитель подтверждает её как доставленную самому себе.

## Оценка кандидата прервана

Состояние testing не означает завершения оценки. Не повторяйте внешние вызовы автоматически: они могли быть оплачены. Человек может отменить эксперимент и инициировать новый. Отчёт inconclusive также не допускает применение. Если ожидание команды мешает применению уже проверенного кандидата, прочитайте его состояние и после завершения работы выполните progress; watchdog тоже попробует продвинуть разрешённого кандидата.

## Откат

Ручные cancel/restore и наблюдения от user требуют одноразового подтверждения; автоматический откат по условиям trial — нет. Процедура: [Подтверждение человеком](CONFIRMATIONS.md). Строка evidence сама по себе не разрешает возврат версии.

Отрицательное независимое наблюдение или истёкший trial возвращают сохранённый исходный текст новой записью версии. `history <role>` показывает кандидата и rollback. Чтение роли на следующем задании должно вернуть восстановленный hash. Старый контекст текущего разговора не является подтверждением нового prompt — bootstrap требует повторного чтения на каждом новом задании.

Если текущая версия не равна ожидаемому кандидату, контроллер фиксирует blocked и не затирает неожиданное изменение. Роль перестаёт читать новую рабочую инструкцию до явного восстановления человеком. Проверьте `version`, события и совместимость. Команда `restore <role> <version-id> --evidence <human-ref>` создаёт новую версию и снимает блокировку; активный эксперимент сначала должен быть закрыт.

Восстановление не отменяет публикации, сообщения, расходы или кодовые изменения. Их нельзя объявлять отменёнными вместе с инструкцией.

## Резервная копия

Для человекочитаемого архива перенаправьте export в файл вне релиза. Для восстановления runtime нужна согласованная резервная копия SQLite, а не копирование одного файла при активном WAL. Используйте стандартный SQLite backup API в доверенном shell-сеансе или остановите работу и скопируйте весь runtime после закрытия процессов. Личные памяти и нативные истории ботов хранятся платформой и в этот backup не входят.

## Обновление и отключение

Релиз закреплён: изменение файлов под уже установленной командой вызывает ошибку проверки целостности при чтении роли. Не заменяйте файлы релиза на лету. Команды, закреплённые на `v1.5.3`, продолжают работать. Для перехода на `v1.6.0` завершите задачи и испытания, сохраните старый runtime и экспорт. Проверьте совместимость контрактов и выполните [INSTALL](../INSTALL.md) с отдельными путями для релиза, venv и runtime. Привяжите проект и проверьте готовность новой команды, затем направляйте ей новые задачи. Старый runtime храните как архив. Если Руководитель остаётся прежним, перед установкой новой команды отключите его прежнее стартовое правило.

Для отключения дождитесь завершения задач, отмените активные эксперименты с откатом, остановите watchdog и по запросу человека удалите только bootstrap-правило команды из памяти участников. Боты и их прошлые разговоры автоматически не удаляются. Без bootstrap существующий бот продолжает прежнюю работу; пользовательские данные не стираются.

## Аварийная остановка

1. Скажите Руководителю «стоп». Он должен заблокировать или отменить задачи команды и ждать вашего решения. Контракт задаёт поведение бота и сам не завершает процессы ОС.
2. Отключите рутину перезапуска или супервизор. Отмените активные испытания с грантами. Выполните `service stop` от `installer` или от `user` с грантом. Убедитесь, что watchdog остановлен.
3. Приостановите или удалите только двух добавленных ботов в Grok Bot. Удалите из памяти участников стартовое правило команды и сохраните прежние инструкции Руководителя.
4. Закройте контроллер и оставшиеся рабочие процессы. Экспортируйте или сохраните нужные записи, затем удалите рабочую папку, если хотите стереть локальное состояние. Удаление не меняет разговоры на платформе и уже выполненные действия.

## Проверка при установке

Smoke использует временный Git-проект. Проверяющий прогоняет общий профиль на исправной и намеренно испорченной версиях. Испорченная версия должна провалить проверку. Этот тест измеряет исполнение команд и доступ к артефакту. Проверьте подлинность нативной передачи в своём аккаунте.

Интервал watchdog по умолчанию — пять секунд. `install-finish` требует живой heartbeat. После перезапуска выполняйте команды тем же интерпретатором venv, который сохранился в bootstrap. При переносе путей нужна повторная привязка.
